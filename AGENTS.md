# Repository Guidelines

## Project Map

- `lib/main.dart` starts the app; `lib/app/noor_app.dart` composes launch, theme, and localization.
- `lib/core/` contains API, data/cache, downloads, models, OAuth, state, sync, theme, torrent, tracking, and Trakt.
- `oledMode` is an opt-in `AppState.webSettings` preference in Appearance. `NovaTheme.darkOled` gives dark screens a pure-black canvas and base surfaces on Android and iOS; light mode stays on the normal light theme, including when System follows a light OS. The player and splash use the active theme canvas.
- lib/core/update/app_update_service.dart validates root version.json and APK content, compares installed build metadata, classifies update failures, downloads to app cache, and opens the package installer. The manifest's build numbers are Android-only; iOS must not offer or require an update from them until separate iOS release metadata exists.
- `lib/core/models/integration_cw.dart` normalizes linked-service playback progress (Trakt/Simkl pause points and AniList/MyAnimeList episode counters); `AppState.refreshLinkedContent` refreshes it, and `AppState.historyForTitle` merges provider episode state with local history for details.
- `lib/core/storage/resume_snapshot_store.dart` saves compressed, expiring video pause frames locally; its metadata stays separate from synced watch history.
- `AppState._persistAndSync` preserves its bucket scope for local writes as well as cloud scheduling. Five-second playback checkpoints persist only history and Continue Watching; addons, custom lists and watchlist are not re-encoded on each save. Full initialization/merge persistence remains available. Existing storage keys, resume durability and sync payloads stay unchanged.
- `lib/core/models/playback_resume_policy.dart` holds the shared resume prompt/seek and last-two-minute completion predicates used by both player routes, checkpoint frame capture, and local history/Continue Watching. These preserve existing short-media and storage semantics; linked-service progress remains separate.
- `lib/features/` contains `shell/`, `home/`, `media/` (details/episodes/sources), `catalog/`, `anime/`, `calendar/`, `live_tv/`, `kids/`, `library/`, `downloads/`, `player/`, `settings/`, `onboarding/`, `splash/`, and torrent handlers.
- `lib/features/player/session/playback_progress.dart` contains immutable progress samples and a latest-value coalescer (100 ms minimum publication spacing, injected monotonic clock/scheduler, generation reset and close cancellation). `playback_progress_binding.dart` owns the route-local display listener and invalidates old engine identities. `VideoPlayerPage` enables this projection only with `--dart-define=NOVA_COALESCED_PROGRESS=true` (default false). Timeline commands use exact engine readers; persistence/feature decisions remain exact. The common engine/page notifier still exists, so this is not full rendering isolation or completion of Station 10. Tests: `playback_progress_test.dart`, `playback_progress_binding_test.dart`, `player_timeline_progress_test.dart`.
- `lib/features/player/playback_entry_page.dart` selects Core by default once per route, before engine allocation; `--dart-define=NOVA_PLAYER_CORE=false` retains Legacy rollback. `session/playback_state.dart` freezes route inputs and defines command outcomes; `playback_session.dart` owns serialized commands, source/resolver generations, exclusive native ownership, progress/transport projections, panel/lifecycle intent and awaitable close. Core retry retains the last positive exact position when a failing backend resets its current position to zero; an explicit seek to zero clears that retry position. `playback_checkpoint.dart` serializes exact immutable checkpoints across core routes through existing AppState/storage APIs; no storage schema or sync keys change. `widgets/player_session_surface.dart` caches the video child until engine identity or fit changes. The legacy page stays selectable until Gate E; runtime/performance acceptance is separate from compilation/tests.
- Both player routes load exact-file chapters and public AniSkip, IntroDB, and TheIntroDB timing after a positive duration; existing stream/episode markers win. AniSkip requires an exact AniZip MAL episode match. `lib/core/storage/skip_timing_credentials.dart` keeps optional IntroDB and TheIntroDB user keys in platform secure storage, outside synced settings; only TheIntroDB's key is sent during timing reads. The linked-services screen manages these keys. Manual skip, resume and next-episode prompts share `PlayerBlurActionPill`; physical-device timing acceptance remains open.
- `lib/features/player/segments/playback_segments.dart` resolves recap, intro, opening, outro and credits markers with source precedence; `skip_segment.dart` tracks overlap suppression and dismissal for both routes. `player_skip_segment_pill.dart` displays the active segment action. `next_episode_policy.dart` centralizes Up Next visibility and guards data-driven auto-advance against manual seeks, pauses, resume, panels, locks and route transitions. Settings can select Core or Legacy via `playerImplementation`; `NOVA_PLAYER_CORE=false` forces Legacy. These player additions have focused static/test evidence only; Stations 14–15 still need their device and LKG gates.
- Android Core reads `playbackBackend` from existing `AppState.webSettings`: Auto (default), Media3 ExoPlayer, or libmpv. Playback settings present this selector first on Android; searching settings for Media3/ExoPlayer/libmpv leads to that page. iOS shows a read-only libmpv engine row because Media3 has no iOS backend. The selector applies to Core; Legacy always uses libmpv. `engine/media3_engine.dart` and `media3_session_backend.dart` adapt `NovaMedia3Plugin.kt` over `nova/player/media3` with generation-safe native IDs, a SurfaceProducer texture, 250 ms progress, native audio focus and optional PixelCopy resume frames. Other platforms use existing media_kit/libmpv. Auto permits one format/decoder fallback after native retirement; HTTP/network/DRM failures do not cause fallback. Nonzero audio/subtitle timing offsets use libmpv, preserving session continuity. Flutter owns all controls and default subtitle styling. Official Media3 modules are pinned together at 1.8.0; no NuvioMobile GPL source or AAR is bundled. See `DUAL_ENGINE_PLAN.md` and `NUVIO_DUAL_ENGINE_RESEARCH.md` under docs/player-reengineering; performance remains NOT MEASURED until physical-device runs.
- `mpvQuality` in existing `AppState.webSettings` defaults to `balanced` and offers performance/balanced/quality picture processing in Playback settings. `engine/picture_quality.dart` maps the two nondefault presets to bounded libmpv scaler/deband/dither properties before the next video opens in both Core and Legacy; balanced keeps native defaults. This changes rendering, not add-on stream resolution. On iOS it applies to libmpv playback; on Android it applies only when libmpv is the active backend, without changing the user's Media3/Auto engine selection. Unsupported native properties leave playback available. Device-visible quality and performance remain unverified.
- Core mounts its cached `PlayerVideoSurface` only after the session reports ready, matching the legacy page's Android video-output lifecycle and avoiding attaching the native surface while the media_kit backend is still opening.
- `MediaKitEngine.open` retains legacy autoplay by default and adds `playWhenReady: false` for the core; `close()` awaits native retirement. Do not mix legacy `dispose()` ownership with core `close()` on the same engine. Apply startup offsets/subtitle-off inside the open generation before play; source continuity overrides startup defaults. Core handoffs revalidate play-intent revision and current lifecycle. Core resolver handoffs must retire native playback before `TorrentService.prepare`, which deactivates an existing torrent. Session explicitly owns current/retiring leases: never stop a torrent before successful native retirement or create another engine after a failed/hanging close.
- Core seek capability is queried at paused open and rechecked for a short bounded period after duration appears; startup resume also waits briefly for a positive result before seeking and playing. Never treat a stale paused-open `seekable=no` as permanent. Invalidate the result and pending probes on source replacement/close, and require a positive capability before accepting seek commands.
- Core close cancels queued command results and retires native playback before waiting on a stuck active command or a checkpoint write. `PlaybackOwnership.retireCurrent` is the detail-page barrier before preparing a new on-device torrent; a failed or timed-out retirement blocks new native creation and reports a localized error. Do not bypass that barrier or release the torrent before native retirement succeeds.
- `StreamServer.close` force-closes the local listener and bounds the drain of already-disconnected requests to two seconds; a stalled piece query must not keep a retired Core route's torrent lease and the next route's ownership barrier open indefinitely. The timeout logs a sanitized diagnostic before native torrent removal.
- The player's timeline follows the user-requested direction convention: Arabic starts on the physical left and English on the physical right. `PlayerBottomCluster` sets that direction explicitly for the progress row so fill, thumb, time labels and tap/drag targets stay aligned even when an ancestor has a different text direction.
- Shared `PlayerUpNextPlacement` constrains the end-of-episode card to the visible landscape viewport and scrolls tall content; `PlayerUpNextActions` stacks its actions on narrow or enlarged-text layouts. `PlayerSecondaryAction` uses a finite minimum width so its unfixed placement in a Row does not invalidate Flutter layout. Keep both player routes on these shared widgets.
- `lib/features/player/temporary_speed_hold.dart` serializes the press-and-hold 2× rate and exact previous-rate restoration across both player routes; source identity invalidates stale commands. Both pages gate gestures while panels, lock or exit are active. A route-local HUD notifier isolates high-frequency seek/brightness/volume feedback; the legacy page also retains its video child through the shared `PlaybackSessionSurface` until engine identity or fit changes.
- `lib/features/player/widgets/player_episodes_sheet.dart` presents seasons and episodes in both player routes with directional cards and constrained layouts. Episode play opens the source picker by default; the existing `AppState.webSettings` key `autoSelectEpisodeSource` is opt-in and defaults to `false`. `widgets/precise_delay_value.dart` supplies the shared 10 ms vertical gesture for audio and subtitle delay, preserving integer millisecond settings.
- `lib/core/data/anime_subtitle_ids.dart` resolves exact AniZip season/episode records to alternate subtitle IDs; `CatalogRepository.subtitlesForEpisode` uses them only when the normal enabled-add-on subtitle search is empty. Both player routes call this repository method. It never changes playback/stream IDs or guesses absolute episode numbers, and a failed lookup leaves the original empty result intact.
- `lib/features/player/engine/external_subtitle_loader.dart` downloads add-on subtitle text through `NoorApi.proxyText`, rejects provider HTTP failures and non-subtitle bodies, and returns a media_kit `SubtitleTrack.data` for valid text. Both routes report typed provider errors without selecting failed URLs. Core source continuity reselects the data-backed track on replacement; one valid external subtitle was user-reported working on the physical Android device, while broader provider/format coverage remains unverified.
- `subUseFileStyle` is an opt-in subtitle appearance preference shared by general settings and both player routes. The default Flutter overlay keeps the user's manual font/weight/position. When enabled, media_kit/libmpv renders the selected track with libass and file-supplied styles; Core hands Media3 to libmpv through its continuity barrier. The Flutter overlay remains visible if native styling cannot activate. mpv's Android font asset is a fallback; exact fonts and file-format behavior need device evidence, especially on iOS.
- `lib/core/storage/subtitle_font_store.dart` keeps imported TTF/OTF subtitle font bytes and a manifest on the device, registers them with Flutter `FontLoader` at launch, and exposes them to the shared subtitle font picker in app settings and the player style sheet. `subFontFamily` is the selected family in existing settings; imported bytes never enter settings sync. `lib/features/player/engine/local_subtitle_picker.dart` copies device-picked subtitle files to the app cache and both player routes offer an import action in the subtitle panel. Core hands local files to libmpv through its existing continuity handoff. File-format compatibility beyond actual engine tests remains unverified.
- Subtitle style stores `subFontBold` (default `false`) in the existing `webSettings` map. The general Subtitle settings switch and the in-player style sheet share this key; `SubtitleStyle` projects it to both player routes' live Flutter subtitle overlay, and the sheet preview uses the same weight. The subtitle picker search field stays compact without shrinking the adjacent 48dp controls.
- Player subtitle panels request `CatalogRepository.subtitlesForEpisode(..., reportFailures: true)` so total add-on failure is shown separately from an empty response; other callers keep the existing tolerant default. `widgets/player_panel_request.dart` invalidates stale panel fetches on refresh, switch, and close in both routes.

Legacy automatic resume uses `engine/startup_resume_seek.dart` to probe paused-open duration/seek capability, then attempts a bounded playing-source seek with position confirmation if paused capability stays unavailable. It suppresses progress writes during that transition and reports failure if the position is not confirmed. Prompt-driven resume remains separate. Legacy disposal uses its retained `AppState` reference for progress saves, never a deactivated widget context.
- `lib/shared/widgets/` holds reusable cards, rails, image helpers, dialogs, parental gates, and loading states. `lib/l10n/` contains Arabic/English ARB sources and generated code.
- `lib/features/media/episode_views.dart` owns detail episode list/grid presentation; long-press actions are wired from `media_detail_page.dart`, while `AppState` stores watched ranges and sends one enabled-service sync per provider.
- `lib/features/home/widgets/continue_watching_rail.dart` renders local and linked Continue Watching cards together in one horizontal rail; `lib/features/media/episode_views.dart` presents episode progress and mark-watched actions; Anime reuses the same linked-progress rail.

## Design System and UI Rules

- Android torrent offline downloads use `DownloadManager.enqueueTorrent`, `NativeTorrentDownloads`, `TorrentDownloadStore` and `NovaTorrentDownloadService` through `nova/torrent_downloads`. A dataSync foreground service owns a separate, single-transfer libtorrent queue independently of the Activity/Flutter engine; it survives ordinary UI/task closure and posts NOVA progress/completion notifications. Source hints and durable native state are encrypted with Android Keystore. Completion requires all selected-file pieces, full size and a video signature; the native session retires before file publication. Cancel/remove await native retirement. Interrupted jobs retain pieces for retry. Force stop and Android background time limits are not bypassed. Android 13+ requests notification permission at download time. Direct Android jobs remain OS-owned; neither native transfer type may enter the Dart HTTP queue. Source selection keeps hashes/magnets and excludes adaptive playlists from offline saving. See `docs/player-reengineering/TORRENT_DOWNLOADS.md` for evidence and platform limits.

- **Decide whether each new UI element needs Liquid Glass from its role and context.** Use Liquid Glass for elements that act as system-style navigation or transient controls and whose hierarchy benefits from the material, on Apple devices and OS versions where the design is supported. If the element is content, a dense information surface, or has no clear benefit from the material, keep NOVA's established themed design. Preserve the appropriate standard NOVA fallback on unsupported Apple OS versions and on Android; honor Reduce Transparency and existing platform/device rules. Do not add glass effects just for decoration or at the expense of readability and interaction.
- Use adaptive `Switch` and `Slider` controls for toggles and value adjustment so iOS presents Apple's Cupertino-style controls while other platforms retain NOVA's Material styling. Keep their existing value ownership, callbacks, accessibility semantics and platform-specific theming intact.
- **Use NOVA's theme colors for app UI.** Do not introduce raw HEX values or `Color(0x...)` literals in feature/widget UI. Read semantic roles from `Theme.of(context).colorScheme`, `NovaTheme.of(context)` / `NovaPalette`, or reuse an existing `NovaColors` token where a fixed brand/status color is intended. Apply opacity to an existing semantic color with `.withValues(alpha: ...)`; do not create a new near-duplicate color inline.
- If a needed semantic color does not exist, add it centrally in `lib/core/theme/nova_theme.dart` with an intentional light/dark role, then consume that role from UI. Do not copy a reference app's palette or add a competing local palette.
- HEX values remain valid for **data**, not UI styling: persisted user-selected subtitle colors, parsed colors received from providers, and serialization/interoperability boundaries may encode colors as strings. Keep conversion in the existing settings/model helpers and map defaults/previews to NOVA theme colors. Asset artwork, SVGs, native platform resources and brand source files retain their appropriate formats.
- Before building a component, inspect `lib/core/theme/`, `lib/shared/widgets/` and the nearest existing feature implementation. Prefer existing shared components (for example `PosterCard`, `MediaRail`, `NovaNetworkImage`, `ShimmerBox`, shared dialogs and messages) and the established Material theme styles. Keep feature-specific pieces local until they have a real second consumer or shared behavior worth extracting; avoid both duplicated shared widgets and premature generic frameworks.
- Reuse `NovaSpace`, `NovaMotion`, the app `TextTheme`, shared icon conventions and existing shapes/elevation. Use `NovaBrand` and documented brand assets for NOVA identity; use Lucide for ordinary controls. Do not invent new spacing, radius, typography, animation or icon systems for one screen.
- Build layouts from available constraints rather than fixed device sizes. Respect safe areas, scrolling, text scaling, keyboard insets, and logical directional APIs (`start`/`end`, `EdgeInsetsDirectional`, alignment) so Arabic RTL and English LTR both work. Panels and dialogs must fit their parent/window and keep their important actions reachable.
- Preserve clear hierarchy, compact density for player controls, adequate touch targets, readable contrast, and accessible labels/states. Honor reduced-motion settings through the shared motion helpers. Do not use a decorative effect at the expense of playback controls or content readability.
- For visible UI changes, verify both dark and light themes, Arabic RTL and English LTR, and representative phone/tablet constraints and enlarged text in widget tests where practical. Report device verification only when a physical device was actually used.
- Reference review: NuvioMobile centralizes theme colors in `ThemeColors.kt` / `AppTheme.kt`; Harbor defines semantic design tokens in `installer/ui/styles/tokens.css`; Jellyfin Android composes UI from `MaterialTheme` roles and themed reusable content. Other reference files include local literals, so use these as evidence for central tokens and theme-aware components, not as permission to copy their palettes or one-off colors into NOVA.

## Build, Test, and Development

- Codemagic's `nova-ios-validation` runs the full `test/` Flutter unit/widget suite before compiling the unsigned iOS app. This does not execute native XCTest or establish physical-device behavior.
- Codemagic must use the repository YAML configuration, not the hosted Workflow Editor's old Debug default. The workflow display name is `NOVA iOS Release IPA (iLoader)` and its app artifact is `Nova-release-unsigned.ipa`. `docs/ios-liquid-glass/19_IPA_FEATURE_PARITY.md` records the platform inventory and device checklist; local P2P/torrent downloads and an iOS background URLSession download service are not implemented, so a successful IPA build does not establish Android/iOS feature parity.
- Download path validation compares the canonical existing parent so Darwin `/var` and `/private/var` aliases retain valid persisted rows. Keep the UUID/file-name check, canonical-root containment and root/leaf symlink rejection; resolve the parent rather than requiring the downloaded file to exist, so missing files remain retryable failures.
- The pinned Codemagic Flutter checkout must run `flutter precache --ios` before a manual `pod install`. macOS `flutter pub get` may generate the previously absent Podfile; its post-install hook requires the pinned checkout's `Flutter.xcframework`, which host analysis/tests alone do not download.

- `flutter pub get` resolves the locked dependencies.
- `flutter analyze --no-pub` checks diagnostics; `flutter test --no-pub` runs unit/widget tests (or pass `test/<name>_test.dart` for one file).
- `dart format lib test` formats code; use `--output=none --set-exit-if-changed` for a check.
- `python tool/generate_nova_l10n.py` regenerates localization code from ARB sources.
- `flutter build apk --release --no-pub` builds Android. An iOS build requires macOS and Xcode.
- Never launch an emulator. Do not claim physical-device verification unless a device was actually used.

## Code Style and Localization

Use standard Dart formatting, two-space indentation, `UpperCamelCase` types, `lowerCamelCase` members, and `snake_case.dart` files. Keep feature state scoped and reuse shared widgets. Add copy to both `lib/l10n/app_en.arb` and `app_ar.arb`, run the generator, and never hand-edit `nova_messages.g.dart`. Use logical directional layout and check RTL behavior.

## Architecture and Compatibility

Preserve app IDs, callbacks, secure-storage and sync keys. Internal `noor` names are compatibility identifiers. Claim provider/device behavior only after real verification.

## Testing and Review

Name tests `*_test.dart`; cover changed behavior, including RTL/LTR and themes for UI. For releases, keep `pubspec.yaml`, `lib/core/version.dart`, and root `version.json` aligned; advance Android build numbers monotonically and test that the previous build sees the manifest as an update, and verify that JSON strings returned as `text/plain` are decoded before validation. Before submitting, run relevant tests/analyzer, inspect `git diff --check`, and disclose checks needing hardware, accounts, or macOS. Publish the updated root manifest before expecting installed clients to discover a release; attach the matching-signed APK to the corresponding GitHub Release before relying on the app download link.

## Commit and Pull Requests

Use concise Conventional Commit subjects, e.g. `feat(player): ...`. PRs should describe behavior, list validation, link issues, and include UI screenshots.

## Security and Configuration

Never commit provider credentials or private signing keys. Keep key.properties and *.jks ignored. Android release builds use the existing debug-key fallback until a complete local android/key.properties is configured; the GitHub workflow has no upload keystore and its APK artifact must not be published as an app update.
